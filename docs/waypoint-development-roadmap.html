Saved-search locations must be confirmed before discovery can run.

Confirmed root cause

The searches 08/06/26 and IT Help Desk had location labels but no confirmed latitude, longitude, provider, or place ID. The discovery service rejected both with Search location is not confirmed.

  • Location resolution is configured and healthy.
  • No role-family provider searches were attempted.

Development implication

The missing Capture & queries workspace is now an operational blocker: the current legacy editor cannot resolve a place and require explicit candidate confirmation. The recovery flow must confirm coordinates before enabling or running a search.

  • Separate “latest run output” from “existing review backlog” in the UI.
  • Explain unresolved-center failures beside the affected search.
  • Prevent enabled searches from remaining unresolved.

Add real Pipeline intelligence

Replace the sample header values with MariaDB-backed activity metrics and introduce composable filters without breaking the visible-only reorder invariant.

  • Applied-this-week, active-interview, response-rate, and overdue-follow-up metrics
  • Text, location, urgency, follow-up, contact, and activity-date filters

Build now

Replace the URL-capture stub

Move URL extraction to a bounded server endpoint. Parse JobPosting JSON-LD first, then metadata fallbacks, and always return an editable draft with safe warnings.

  • Block private, loopback, link-local, reserved, and credential-bearing targets
  • Pin DNS resolution and revalidate redirects to prevent rebinding
  • Enforce redirect, timeout, response-size, and content-type limits
  • Extract role, company, location, and salary when available

Technical debt

Known constraints to manage deliberately.

These are not all immediate feature blockers, but they define the safe operating boundary and the cost of future change.

No application authentication

Tailscale is the only access boundary. Do not publicly bind or expose the server until authorization is designed.

No continuous integration

Tests and deployments are manual, increasing the chance that a dependency or feature regression reaches production.

No component or hook tests

The test suite exercises pure logic, services, and APIs, but no DOM environment is configured for React behavior.

Forward-only migrations

Application code can roll back to a prior release; database rollback requires a verified backup when explicitly necessary.

Desktop-first layout

The supported application shell has a 1280-pixel minimum width. Mobile behavior is not part of the current product contract.

GitHub CLI authentication is stale

The local checkout shows only master, but live issues and pull requests could not be inventoried until the CLI token is renewed.
