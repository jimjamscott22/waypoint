# Waypoint Insights Implementation Plan

> **Execution:** Implement inline, task-by-task. The user explicitly requested no subagent workflow and no TDD; each task adds focused tests after the implementation and ends with a verified commit.

**Goal:** Add a working Insights navigation section that presents a 90-day outcome-first command center, records accurate stage history, and links recommendations back to Pipeline.

**Architecture:** MariaDB remains authoritative. A new repository reads analytics source rows, a pure builder turns them into the API response, and a focused service exposes `GET /api/insights`. The existing `useJobsStore` remains the only frontend state source and conditionally composes Pipeline or Insights inside the current app shell.

**Tech Stack:** React 18, Vite 8, Fastify 5, MariaDB 10.6+, JavaScript, inline styles using `src/theme.js`, Node's built-in test runner.

## Global Constraints

- Default range is `90d`; supported values are `30d`, `90d`, and `all`.
- Do not add React Router, a charting library, a CSS framework, or a frontend test framework.
- Keep all job-related application state in `useJobsStore`.
- Keep MariaDB aggregation inputs server-side; the client receives only the Insights response.
- Do not fabricate pre-migration stage transitions.
- Pipeline and Insights are interactive; Capture & queries and Contacts remain unavailable.
- Use code-native HTML/SVG charts with exact text values and keyboard-readable controls.
- Preserve the app's `minWidth: 1280` desktop-first layout.

```sql
ALTER TABLE jobs
  ADD COLUMN next_action_at DATETIME(3) NULL AFTER next_action,
  ADD KEY jobs_next_action_at (deleted_at, next_action_at);

CREATE TABLE IF NOT EXISTS job_stage_events (
  id CHAR(36) PRIMARY KEY,
  job_id CHAR(36) NOT NULL,
  from_stage VARCHAR(30) NULL,
  to_stage VARCHAR(30) NOT NULL,
  occurred_at DATETIME(3) NOT NULL,
  CONSTRAINT job_stage_events_from_stage_check
    CHECK (from_stage IS NULL OR from_stage IN ('Saved', 'Applied', 'Interviewing', 'Offer', 'Closed')),
  CONSTRAINT job_stage_events_to_stage_check
    CHECK (to_stage IN ('Saved', 'Applied', 'Interviewing', 'Offer', 'Closed')),
  CONSTRAINT job_stage_events_job_fk
    FOREIGN KEY (job_id) REFERENCES jobs(id) ON DELETE CASCADE,
  KEY job_stage_events_job_time (job_id, occurred_at),
  KEY job_stage_events_time_stage (occurred_at, to_stage)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

INSERT INTO job_stage_events (id, job_id, from_stage, to_stage, occurred_at)
SELECT UUID(), id, NULL, stage, UTC_TIMESTAMP(3)
FROM jobs
WHERE deleted_at IS NULL;
```

### Task 2: Build Deterministic Insights Metrics

**Files:**
- Create: `server/insights/buildInsights.js`
- Create: `tests/insights.test.js`

**Interfaces:**
- Consumes: normalized snapshot `{ jobs, events, listingMatches, queries, historyCoverageStartsAt }`.
- Produces: `parseInsightsRange(range, now)` and `buildInsights(snapshot, { range, now })` matching the approved response.

- [ ] **Step 1: Implement range parsing and metric helpers**

Export:

```js
export const INSIGHTS_RANGES = ['30d', '90d', 'all'];

export function parseInsightsRange(range = '90d', now = new Date()) {
  if (!INSIGHTS_RANGES.includes(range)) {
    throw new AppError(400, 'INVALID_INSIGHTS_RANGE', 'Range must be 30d, 90d, or all');
  }
  if (range === 'all') return { range, startsAt: null };
  const days = range === '30d' ? 30 : 90;
  return { range, startsAt: new Date(now.getTime() - days * 86_400_000) };
}
```

Use UTC Monday week starts, return `null` for zero-denominator rates, and round displayed rates to one decimal place.

- [ ] **Step 2: Implement cohort, funnel, and weekly activity**

The cohort is the set of distinct jobs with a non-baseline transition into Applied on or after `startsAt`. For each cohort job, inspect all later events and record the furthest of Applied, Interviewing, or Offer. Build monotonic funnel counts and weekly stage-entry totals.

Baseline events are identified by `fromStage === null` and never count as applications or interviews.

- [ ] **Step 3: Implement discovery aggregation**

Filter `listingMatches` by `firstMatchedAt`, deduplicate overall listings by `listingId`, and attribute a listing to every query row it matched. Compute:

```js
{
  matchesFound,
  reviewedResults,
  savedListings,
  saveRate,
  dismissedListings,
  queries: [{
    id,
    name,
    enabled,
    matchesFound,
    reviewedResults,
    savedListings,
    saveRate,
    averageScore,
  }],
}
```

Sort query rows by save rate descending, then reviewed count descending, then name.

- [ ] **Step 4: Implement prioritized recommendations**

At a stable `now`, generate:

1. `follow-up-due` for active jobs with `nextActionAt < now`.
2. `stalled-applied` for Applied jobs whose latest stage event is at least 14 days old and which have no future next action.
3. `stale-saved` for Saved jobs whose latest stage event or creation time is at least 7 days old.
4. `low-performing-query` for enabled queries with at least 10 reviewed results and save rate below 10 percent.

Sort in the order above, oldest/due-earliest first within each category. Return job recommendations with `jobId` and `stage`; return query recommendations with `queryId`.

- [ ] **Step 5: Add unit coverage after implementation**

`tests/insights.test.js` must cover:

- `30d`, `90d`, `all`, and invalid range.
- Baseline events excluded from applications.
- A cohort job progressing Applied → Interviewing → Offer counts once at each funnel level.
- A return to Applied adds weekly activity but does not duplicate the cohort.
- Zero applications returns `interviewRate: null`.
- Monday UTC week bucketing across a month boundary.
- One listing matched by two queries counts once overall and once per query.
- Unreviewed/expired listings excluded from save-rate denominator.
- Recommendation threshold at exactly 10 reviews and 10 percent.
- Priority order and future `nextActionAt` suppression.
- Coverage completeness for finite and all-time ranges.

```js
export function toLocalDateTimeInput(iso) {
  if (!iso) return '';
  const date = new Date(iso);
  if (Number.isNaN(date.getTime())) return '';
  const local = new Date(date.getTime() - date.getTimezoneOffset() * 60_000);
  return local.toISOString().slice(0, 16);
}

export function fromLocalDateTimeInput(value) {
  if (!value) return null;
  const date = new Date(value);
  return Number.isNaN(date.getTime()) ? null : date.toISOString();
}
```
